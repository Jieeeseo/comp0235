# COMP0235-zczqh91

## Overview

This repository contains the infrastructure and configuration for the COMP0235 project. It includes Terraform scripts for provisioning resources and Ansible playbook for configuring the environment.

## System Architecture

- **Infrastructure**: 5 VMs (1 host node and 4 worker nodes) on Harvester
- **Automated Configuration System**: Ansible.
- **Task Queue**: RabbitMQ.
- **Distributed Workers**: Celery 
- **Storage**: NFS
- **Monitoring**: Prometheus & Grafana 

## Directory Structure

- `build_cluster/`: Terraform scripts to provision the VMs.
- `ansible/`: Ansible playbooks, roles, and inventory configuration.

## Quick Start

**Note:** Run these steps on your local machine or external master node.

1. **Clone the repository**

	```
	git clone https://github.com/Jieeeseo/COMP0235-zczqh91.git
	cd COMP0235-zczqh91
	```

2. **Initialize and apply Terraform**

	Ensure your `variables.tf` is configured with your credentials.

	```
	cd build_cluster
	terraform init
	terraform apply
	```

	*This will create 1 Host VM and  4 Worker VMs.*

3. ***Modify inventory***

	You can use the provided script to check the IP addresses of the host and worker nodes generated by Terraform, then update the static inventory file `inventory.ini` in the `ansible/` directory.

	```
	python3 generate_inventory.py --list
	```

	After confirming the IP list, edit `ansible/inventory.ini` and replace the IP addresses under `[host]` and ` [workers]`

## Cluster Configuration (Host Machine)

**Note:** All configuration and pipeline execution happen on the **Host Machine**.

1. **Transfer the `ansible` directory to the Host:**

	Use `scp` to copy the `ansible` folder and your private key to the Host machine (IP obtained from Terraform output).

	```
	# Example command (run from local machine)
	scp -r -i ~/.ssh/comp0235 ansible/ almalinux@<HOST_IP>:~/
	scp -i ~/.ssh/comp0235 ~/.ssh/comp0235 almalinux@<HOST_IP>:~/.ssh/
	```

2. **SSH into the Host Machine:**

	```
	ssh -i ~/.ssh/comp0235 almalinux@<HOST_IP>
	```

3. **Prepare the Environment:**

	On the Host machine, set permissions for the private key (required for Ansible to connect to workers).

	```
	chmod 600 ~/.ssh/comp0235
	```

4. **Run Ansible Playbook:**

	Install Ansible (if not already installed) and run the full configuration.

	```
	cd ~/ansible
	sudo dnf install ansible -y
	
	# Run the playbook
	ansible-playbook -i inventory.ini full.yaml --private-key ~/.ssh/comp0235
	```

	*This will configure NFS, RabbitMQ, Celery Workers, and Monitoring services across all nodes.*

## Running the Pipeline

**Note**: All commands below should be executed in this work directory:

```
cd /opt/calc_engine/
```

1. **Check System Status**
	Ensure all workers are online and connected to the Celery app.

	```
	python3 -m celery -A celery_app status
	```

	*Expected output: 4 nodes with status: OK*

2. **Dispatch Tasks**

	The `dispatcher.py` script reads `experiment_ids.txt` and pushes tasks to the RabbitMQ queue.

	**Recommendation:** Run inside a `tmux` session to prevent interruption.

	```
	# Start tmux
	tmux new -s pipeline
	 
	# Run dispatcher
	python3 dispatcher.py
	```

	*Detach from tmux using `Ctrl+B` then `D`.*

3. **Monitoring Progress**

- **Prometheus**:  You can verify whether Prometheus is successfully scraping metrics from all nodes by visiting `https://prometheus-zczqh91.comp0235.condenser.arc.ucl.ac.uk/targets`

​	Expected output: All targets (e.g., `node_exporter`,`rabbitmq`) should show status **UP**.

  - **Grafana Dashboard:** You can monitor real-time system metrics via `https://grafana-zczqh91.comp0235.condenser.arc.ucl.ac.uk/`

  - **Command Line Progress:**

	Check the number of generated result files in the NFS share:

	``````
	ls -1 /nfs/data/results/*.json | wc -l
	``````

4. **Collate Results**

	Once the queue is empty and file count matches the input list, run the collator:

	```
	sudo python3 collator.py
	```

	This will generate two files in the current directory:

	1. `hits_output.csv`: Best hit for each protein.
	2. `profile_output.csv`: Mean statistics (STD and Geometric Mean).

## Key Design Choices

- **NFS:** Used to share the massive `pdb70` database to avoid downloading it on every worker, saving disk space and bandwidth.
- **Celery & RabbitMQ:** Chosen for robust asynchronous task handling. If a worker fails, the task is not lost (Message Durability).
- **Idempotency:** The pipeline script checks if a result JSON already exists before processing. Rerunning `dispatcher.py` will only process unfinished tasks.
